# Codex Goal：已有量子化学数据的补全与持续扩展

项目：**gqcdataset**。远程仓库：<https://github.com/jinzhezenggroup/vibedataset>。

日期：2026-11-18（Asia/Shanghai）。这是依据当前可见讨论重建的交接任务；材料来源和缺件见 [PROVENANCE.md](PROVENANCE.md)。

除非明确注明“仓库根目录”，本文及交接文档中的 `research/`、`sources/`、`templates/` 等相对路径均以 `handoff/gqcdataset_codex_goal/` 为基准。实现代码可放在仓库中合适的位置，研究证据集中维护于上述 `research/`。

## 总体目标

研究如何利用已有量子化学信息，在明确的物理定义与质量要求下，以尽可能少的新增计算获得新的科学信息，并让这些信息持续支持后续的数据扩展。

研究对象包含分子与构型、物性、理论方法、数值精度及已保存的中间信息。不要把目标提前缩成“给某个数据集补一列物性”。需要回答：

1. 已有信息对哪些目标已经充分，能合法省去哪些工作？
2. 缺失的信息应该通过推导、状态转换、学习、精修、响应计算或完整求解中的哪些路径获取？
3. 路径如何满足科学质量要求，其全部新增成本和失败风险是多少？
4. 本轮留下哪些资产，才能降低下一轮扩展的成本？

## 当前共识与研究空间

保留以下五条主线，不预先选择唯一课题：

| 主线 | 核心问题 | 需要形成的证据 |
|---|---|---|
| 目标相关的信息充分性 | 现有观测、状态及元数据能否支持当前目标？ | 可计算的前提、合法变换、反例和不充分条件 |
| 剩余科学程序生成 | 已知数据怎样参与科学程序化简，同时保持导数与响应依赖？ | 替代规则、依赖保留、失效规则和正确性验证 |
| 数据集级信息获取 | 下一项计算对多个目标、样本和后续任务带来多少信息？ | 成本/收益模型、共享机制和逐项强基线 |
| 目标相关质量控制 | 哪些证据足以接受结果，何时需要精修或重算？ | 误差证据层级、接受准则、校准与失败边界 |
| 可持续扩展的数据资产 | 哪些中间信息值得保存、压缩、恢复或重算？ | 存储—计算权衡、未来任务成本和多轮结果 |

GQC 与 xTBloom 是需要深入审计的工作基础。应当进入科学方程、状态依赖与执行机制内部研究，允许在许可证和项目规范允许的范围内修改底层实现。已有公开接口不自动等于完整运行能力；当前文档中的架构候选不自动等于已完成实现。

## 必须以完整可获取源码为路线依据

从 [源码目录](sources/CATALOG.md) 开始，但不能止于这张清单。对影响路线和创新判断的相关工作：

- 确认官方论文、文档、原始仓库或正式归档之间的对应关系；区分论文版本与当前版本。
- 获取完整所选版本源码树，固定完整提交与必要依赖，覆盖测试、构建、生成器、示例、基准、子模块和必要 LFS 资产。
- 建立完整目录/文件覆盖台账；明确获取、索引、阅读、行为追踪、执行验证的不同状态。
- 追踪关键能力的入口、科学身份、状态和约束、核心算法、缓存/共享、失败恢复以及测试。
- 所有影响结论的主张落到固定版本的代码与测试。没有找到代码时，记录搜索证据及判断限制。

遵守 [SOURCE_AUDIT_PROTOCOL.md](docs/SOURCE_AUDIT_PROTOCOL.md)。不能用 README 对比代替源码对比，不能把自动索引写成“已通读全部源码”。也不能以无限源码调研推迟能够改变判断的验证。

## 科学与评价边界

遵守 [VALIDATION_FRAMEWORK.md](docs/VALIDATION_FRAMEWORK.md)，至少包含：

- 分开记录存档态后处理、目标态求解、响应/导数与统计预测；方法及性质定义不能混淆。
- 方法、基组、表示、单位、几何、状态分支和数值质量的适配检查。
- 对状态值复用与隐式依赖分别建模，特别检查冻结态导数与真实响应的差别。
- 采用已有后处理、合适的热启动、原生批处理、缓存及组合计算等强基线；比较一致的科学目标。
- 计算读取、转换、验证、学习训练/推理、求解、失败恢复、重算和存储成本，明确一次性成本及摊销条件。
- 统计实际缺失机制、失败样本、覆盖率、科学质量和跨轮复用价值；保留负结果。

## 执行顺序

详细入口见 [issues](research/ISSUES.md) 与 [ROADMAP_AND_ACCEPTANCE.md](docs/ROADMAP_AND_ACCEPTANCE.md)。

1. 接管仓库与环境，建立来源、版本、源码完整性和覆盖台账。
2. 可并行审计 GQC/xTBloom、最接近外部实现、候选数据资产与强基线。
3. 形成五主线比较，提出具体可证伪假设和竞争解释，选择能减少关键不确定性的实验。
4. 实现足以检验机制的最小科学路径，验证正确性、适用边界与失败行为。
5. 在证据支持时扩展到异构记录和多轮任务，解释成本收益归因并更新研究路线。

阶段推进以证据为条件。早期微型验证可以与审计并行；正式路线选择必须说明最接近前人、差异机制及已有证据。QMugs 四极矩、历史样本数和接口草案只作候选。

## 第一次执行应该交付什么

先读取根目录 `AGENTS.md` 和交接文件，然后在 [STATUS.md](research/STATUS.md) 记录实际接管状态。在 `research/` 子目录建立：

- `sources.lock.json`：仓库/归档、不可变版本、许可证、完整性与子模块/LFS 状态。
- `source_coverage.csv`：完整索引及真实人工阅读/行为追踪状态。
- `audits/`：GQC/xTBloom 及相关实现的证据化审计。
- `claims.csv`：主张、代码/论文证据、适用边界、竞争解释与置信层级。
- `DATASET_ASSETS.md`：候选资产可获取性、状态内容、科学协议及缺失机制。
- `ROUTE_COMPARISON.md`：在完成关键证据后填写，不能预填创新结论。

可从 [模板](templates/) 起步。第三方完整 checkout 默认位于仓库未跟踪的 `_references/`；将可复现获取方式和审计证据提交进仓库。

## 完成标准

最终应给出有源码证据的前人能力地图、GQC/xTBloom 可继承能力与实际缺口、可证伪研究命题、正确性通过的实现、同目标强基线对照、全成本与失败分析，以及可继续扩展的数据/状态资产规范。若实验不支持假设，应交付可复现负结果与路线修订，不能用包装性措辞宣称成功。

本 Goal 不是要求一次启动就完成全部研究。每轮应完成有验收标准的可审查增量，持续推进已满足依赖的工作，在状态和 issues 中留下下一步。未获得执行能力时如实列出阻塞与已经完成的内容。
