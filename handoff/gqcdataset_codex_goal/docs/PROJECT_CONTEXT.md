# 项目背景、已确认要求与未决问题

更新：2026-11-18。项目名：**gqcdataset**。目标仓库：<https://github.com/jinzhezenggroup/vibedataset>。

## 1. 本文的来源与用途

本文依据本次会话可见的项目讨论、用户要求和此前交接包说明重建，用于让 Codex 接管研究与工程工作。它不是此前 ZIP 的逐字恢复，也不是原始 PDF 的转录。当前会话没有提供 `gptchataboutgqc.pdf`、`gqc_completion_design.pdf` 或原 ZIP 的可读取副本，因此不能声称已经恢复、审阅或上传了这些附件。

本次交接首先恢复能够独立执行的文字要求。以后获得原始附件时，应核对遗漏与冲突并补充来源记录；不能让缺失附件阻塞可以依据当前明确要求开展的源码审计。

## 2. 用户已经明确的方向

用户希望研究已有量子化学数据集的补全与持续扩展，并已指定远程仓库作为实际协作场所。最近的要求有三项：

1. **先保留较大的研究空间。** 不因某个物性示例容易实现，就提前把研究收敛成单一课题。
2. **路线规划必须参考现有类似工作的全部可获取源码。** 获取完整源码树、固定版本、建立覆盖记录，然后依据关键实现、测试和实际行为进行判断。仅阅读论文摘要或 README 不够。
3. **交接应能直接驱动 Codex 工作。** 文件、issues、阶段验收和后续任务应相互衔接，持续产出可检查的证据。

GQC 可以作为进入科学方程与编译过程内部的研究基础，允许在必要时研究底层修改；xTBloom 是重要的执行设计参照。是否需要修改、修改哪一层、当前代码已经支持什么，均须由源码与实验决定。

## 3. 总体研究问题

> 在明确的物理定义与质量要求下，如何利用已有量子化学信息，以较少的新增计算获得新的科学信息，并让这次新增的信息降低以后扩展数据集的成本？

这里的“补全”不只表示预测数据表中的空值。已有数据可以沿着以下维度不完整：

**分子与构型 × 物性 × 理论方法 × 数值精度 × 已保存的中间信息。**

缺失的来源也可能不同：结果未导出、表示不兼容、仅有可用初猜、缺少响应、只剩标量观测、原计算失败，或原结果达不到新用途的质量要求。这些情况应分别建模和评估。

## 5. 必须保留的科学区分

### 5.1 已定义的问题与足以省去计算的信息

几何结构与完整模型通常能够定义待求问题。本项目所研究的“信息不足”，主要指现有资产不足以直接得到目标，或者不足以合法省去某类计算，不能笼统写成该问题在数学上没有定义。

只有若干标量性质时，一般不能未经证明就恢复唯一电子态。反过来，得到某个目标也不一定需要恢复完整电子态：特定目标可能只依赖已知观测的一部分、受约束的组合或可验证的中间量。

### 5.2 固定态性质、目标态性质与导数响应

- **固定态后处理**：对一份给定状态，按明确算符与约定计算性质。
- **目标协议下的性质**：先确保状态符合指定方法、状态分支与收敛要求，再计算性质。
- **导数或响应性质**：需要明确状态对外场、核坐标或其他参数的依赖，不能因已缓存状态数值就把这种依赖删除。

存档态可能足以完成第一类任务，但只能作为第二类任务的初猜；第三类还可能需要额外的响应或伴随求解。是否可以省去这些步骤是待证明的条件，不能由文件扩展名或“有波函数”三个字判断。

### 5.3 三种标签语义

输出至少应能区分：在指定协议下求解并验收的 QC 结果；在明确近似与适用范围内得到的结果；带有来源和不确定性说明的统计预测。它们均可能有科学用途，但不能无标记混为同一种真值。

## 6. 建议研究的解耦边界

下表是待验证的设计原则，不是对当前仓库实现的描述。

| 层次 | 应负责的问题 | 不应替代的判断 |
|---|---|---|
| 数据与来源适配 | 原始数据包含什么；单位、几何、状态、模型和表示怎样识别 | 不能仅因字段齐全就判定科学可复用 |
| 科学定义与依赖 | 目标是什么；依赖哪些状态、算符、方程、响应与约束 | 不预先绑定某个批大小或设备 |
| 复用与剩余计算规划 | 已有资产满足哪些前提；哪些节点可替代；哪些依赖必须保留 | 不把缓存命中等同于质量验收 |
| 数值与执行策略 | 采用何种求解、精修、批处理和失败恢复；实际代价如何 | 不改变目标的科学身份来换取表面加速 |
| 验证与证据 | 结果满足什么要求；依据是什么；成本和失败如何归因 | 不把“没有发现错误”升级为严格证明 |

这些边界可以帮助识别应修改 GQC 的哪个内部机制，以及哪些职责适合由数据集侧承担。最终划分必须解释它如何带来新的能力，而不只是增加接口层。

## 7. 后续决策应由什么推动

优先解决会改变路线选择的不确定性：最近邻实现到底已经做到哪里；已存信息在何种条件下能替代求解；状态复用是否保持响应正确性；新增验证成本是否抵消节省；一次保存的状态是否能降低后续轮次的成本。

源码获取和索引不能无限替代研究。关键行为已经追踪清楚后，应开展最小但足以区分解释的验证。同时，验证样例的成功不能自动代表全局路线已经成立。
