# 科学验证、质量与成本框架

更新：2026-11-18。用途：约束后续源码审计、路线比较、实现与实验；不预填任何实验结论。

## 1. 先明确比较的科学任务

每次实验先写清目标，而不是先选择最快路径。目标定义至少包含体系与几何、总电荷和自旋、电子态与分支、理论方法及其参数、实际基组或表示、数值设置、物性定义、单位、坐标与原点约定，以及目标质量要求。

对不同任务必须分别报告：

| 任务 | 验收对象 | 常见误判 |
|---|---|---|
| 固定态后处理 | 给定状态上的指定算符或函数值 | 把任意存档态当作已收敛目标态 |
| 指定协议下的 QC 标签 | 符合目标协议和状态要求的结果 | 仅因数值接近就忽略方法或分支差异 |
| 导数与响应 | 指定扰动下包含正确依赖的变化量 | 缓存数值后截断状态的隐式依赖 |
| 近似补全 | 明确近似条件下的误差与适用范围 | 把近似标签写成相同级别的 QC 真值 |
| 统计预测 | 独立评估的预测误差与不确定性 | 把伪标签直接混入参考标签 |

同一数字相近不等于任务相同。改变方法、基组、状态、物性定义或验收要求后得到的速度提升，不应归因于复用算法。

## 2. 资产身份与可复用前提

对每份输入资产记录可得的身份信息，未知值保持未知。最低限度检查：

- 来源记录、版本、内容散列与生成路径；是否经过转换或压缩。
- 原子顺序、元素、坐标、单位、总电荷、自旋和边界条件。
- 方法、泛函或哈密顿量参数、实际基组参数、有效芯势、积分及近似设置。
- 状态种类、分支、占据、轨道或密度约定、收敛状态及其证据。
- 基函数与轨道顺序、归一化、实球/笛卡尔表示、相位或规范约定等与目标有关的信息。
- 物性算符、电子/核贡献、张量定义、坐标系、原点与单位。

并非每项对每个目标都同等必要；规则应解释哪些是硬前提，哪些可以转换，哪些对当前目标无关。不能因为元数据不全就默默假定兼容，也不能把不必要的条件当作普遍拒绝理由。

格式校验和物理一致性校验可提供必要证据，但不能自动证明资产适合所有目标。检查通过时，记录检查的范围与盲点。

## 3. 复用判定的正反样例

实现一个复用规则时，同时设计应接受和应拒绝的样例。重点覆盖会改变科学身份或依赖的差异：原子排列、几何变化、状态分支、电荷与自旋、方法参数、基组、坐标变换、单位、原点、数值质量和响应需求。

对合法变换，应检查目标是否遵守预期变换规律，而非简单要求所有数值相同。规则允许近似时，近似误差和接受条件必须显式报告。

记录至少四类结果：正确接受、错误接受、正确拒绝、错误拒绝。保守拒绝可以保护质量，但会降低覆盖和性能，因此也需要评价。未知情况应进入明确的补充验证或重算路径。

## 4. 导数与响应的专门验证

复用状态数值后，应追踪状态方程、约束和目标对扰动参数的依赖是否仍然存在。验证对象不仅是最终值，还包括执行了哪些必要的响应或伴随步骤。

可采用与可信独立路径的比较、适用的解析关系，以及经过步长与收敛敏感性分析的有限差分。有限差分自身也有截断误差、数值噪声和分支变化风险，不能只取一个步长就作为普遍真值。

当比较不同路径时，明确其中是否有冻结状态、冻结轨道、冻结基组或其他约束。只有相同导数定义下的结果才应直接比较。

## 5. 质量证据分层

| 层级 | 可以支持的表述 | 仍需说明的限制 |
|---|---|---|
| 结构与身份检查 | 输入满足已检查的格式、身份或变换条件 | 未证明目标误差足够小 |
| 残差与内部一致性 | 指定方程或约束满足到报告精度 | 小残差不自动给出所有物性的误差界 |
| 独立参考比较 | 在给定样本和参考协议下观察到的偏差 | 参考自身误差、样本范围与外推限制 |
| 校准误差估计 | 在明确校准与检验条件下的经验覆盖 | 分布变化、稀有失败及校准假设 |
| 严格界或证明 | 在列出的数学前提下成立的界 | 前提是否可检查、常数是否可用、适用域 |

软件接口出现 `error_bound`、`precision` 或类似名称，不能代替相应证据。实验观察不能升级成严格界；严格界过松也不能自动证明工程上有收益。

分别记录数值求解误差、表示或转换误差、模型近似误差和学习误差。没有可靠分解方法时，应说明观测到的是组合误差，避免重复计入或错误归因。

## 6. 强基线与消融

基线由研究问题和源码证据选择，至少考虑最相关的以下类别：

- 合理实现的从头目标计算。
- 已有波函数或密度的成熟后处理路径。
- 兼容条件下的热启动与适当收敛控制。
- 已有批处理、持续上下文与逐样本失败处理。
- 输入内容缓存、工作流复用和组合方法中的共享计算。
- 对应问题中的成熟多保真、Δ-learning、主动学习或状态学习方法。
- 能表达同类规则的手工实现或简单规划启发式。

不必无差别运行所有类别，但必须解释被选中的最近邻与被排除项。基线应获得同等调参和工程合理性；其实际能力须由固定版本代码与运行记录支持。

消融应能归因：去掉充分性规则、响应依赖保留、共享规划、目标质量控制或资产保存策略，分别改变了什么？如果多个机制不能独立关闭，应设计其他可区分的比较，而非宣称所有收益来自所有模块。

## 7. 端到端成本口径

统计实际新增成本，并明确计时边界。至少考虑数据读取与解压、解析、身份核对、表示转换、积分与状态求解、响应与后处理、验证、模型训练与推理、计划生成、调度、数据传输、保存、失败重试和必要重算。

同时报告可解释的分项和端到端总量。时间、内存、存储、能耗或货币成本若使用，应明确测量方法；不同设备上的峰值理论吞吐不能直接替代实际成本。

以下条件必须保持可比或明确分层：硬件、线程与并发、数值精度、软件版本、编译选项、缓存状态、预热、输入顺序和批处理策略。重复实验应对应计时噪声与数据异质性；不能只保留最快一次。

一次性成本与摊销成本分别报告。训练、预处理、源码编译或状态生成的费用若不计入某张图，必须在相邻文字说明，并提供合适的盈亏平衡分析。

## 8. 数据、缺失机制与困难样本

数据集选择应基于可获取资产、科学目标、授权与可复现性，而不是预先固定某个数据集为唯一验证对象。真实缺失、随机遮盖、按物性遮盖、按方法遮盖、失败相关缺失与质量不足，应在有意义时分开评价。

避免仅在成功记录或容易分子上比较。保留原始分母，说明排除规则与原因；困难情形可包括不收敛、近简并、开放壳层、表示不兼容或不完整元数据，但具体类别应由任务范围决定。

有学习组件时，说明训练、校准、验证与测试的拆分。分子、构型、同源状态或数据处理链带来的泄漏应明确检查。不同补全路径不得通过访问测试标签获得不公平优势。

## 9. 失败与覆盖统计

报告计划输入数、可解析数、满足前提数、直接接受数、精修数、回退重算数、最终成功数和失败数；各阶段分母明确。按失败原因区分身份缺失、规则拒绝、数值失败、资源限制、质量超标和软件错误。

失败不能通过删除日志或缩小分母消失。质量覆盖与计算覆盖应同时报告；在成功子集上观察到的速度不能代表整个目标数据集。

每个失败保留足以复现的最小输入或资产引用、环境、错误信息和状态，但避免复制不必要的大型数据。重试策略也属于算法成本与行为，应固定并记录。

## 10. 多轮扩展与资产价值

至少在需要支持“持续扩展”结论时，设计多个顺序目标或任务分布，比较只保存标签、保存完整状态、保存选择性中间量、压缩资产和按需重算的策略。

累计成本应包括首轮生成、保存、读取、转换、验证与后续失效重算。报告资产大小、恢复成功率、可支持目标范围、后续边际成本，以及任务分布改变后的敏感性。

如果某策略需要预先知道未来物性，明确注明这一条件。不要用事后挑选的任务序列证明普遍最优。

## 11. 最低可复现记录

每个影响路线的实验应具备：研究问题与假设 ID；所有相关代码的完整提交 SHA；数据版本和内容标识；执行命令；环境与硬件；配置和随机种子；输入与输出位置；原始计时与失败记录；评价脚本；结论和限制。

大体积第三方代码、数据和结果采用适当的外部保存或获取方式，仓库中保留锁定信息、清单与复现入口。遵守来源许可；不能因公开可读就假设可以任意重新分发。

## 12. 结束一轮验证的标准

一轮验证应能明确回答：哪项主张被支持、被削弱或被推翻；哪个竞争解释仍然可能；哪些适用条件已经被检查；什么剩余不确定性值得下一步投入。

只在仍有具体风险或必要验收门槛时扩大测试。不要以无限补充基准替代决策，也不要为达成预期结论而事后修改成功标准。使用 [实验记录模板](../templates/experiment.md) 与 [决策记录模板](../templates/decision.md) 保存变化。
